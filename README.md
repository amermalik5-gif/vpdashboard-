# لوحة أولويات نائب الرئيس

لوحة مشتركة للمهام والفعاليات في جدول واحد: يحدد نائب الرئيس **النوع (فعالية، إطلاق، خبر، إعلان داخلي، إعلان على الموقع، أخرى) والمستوى ودرجة الأهمية ومستوى الاستعجال والتاريخ و«المخرج النهائي المطلوب» و«توجيهات نائب الرئيس»**، ويحدّث الفريق **الجهد ونسبة الإنجاز والحالة و«جاهز للإطلاق» و«ملاحظات الفريق» والمسؤول والراعي (المدير العام) و«جزء من» وروابط المخرجات وتاريخ الإطلاق الفعلي** (تظهر نجمة ★ بجانب البند الجاهز في كل مكان، وخانة في الشريط العلوي تعرضها وحدها في الجدول)، وكل ذلك يُعدَّل مباشرة في الجدول، فتظهر الصورة في:

- **مصفوفة الأهمية والاستعجال**: كل بند فقاعة مرقّمة، حجمها يمثل الجهد ولونها يمثل الحالة: رمادي لم تبدأ، أخضر فاتح على المسار، برتقالي متأخرة قليلًا، أحمر متأخرة (ويصبح كذلك تلقائيًا ما فات تاريخه)، أخضر مكتملة. البنود التي لم تُقيَّم بعد تنتظر أسفل المصفوفة، وتُسحب إليها لتحديد أهميتها واستعجالها. وبجانبها قائمة البنود بأرقامها، ويمكن لمن سجّل الدخول سحب أي بند فيها (من مقبض ⋮⋮) لتغيير ترتيبه ورقمه، فيتغيّر الرقم في الفقاعات والجدول أيضًا.
- **المهام المتأخرة**: كل بند غير مكتمل تجاوز تاريخه تظهر بشارة «متأخرة» في الجدول والمصفوفة والخط الزمني، وبعدّاد في الشريط العلوي. البند «المتوقف» لا يصبح أحمر، والبند الذي سُجّل تاريخ إطلاقه الفعلي لا يُعدّ متأخرًا.
- **إشارات المتابعة** (اجتماع ١٨ نوفمبر ٢٠٢٦): لكل بند مسؤول إلزامي (وإلا تظهر «بلا مسؤول»)، وكل بند أحمر أو برتقالي يحتاج سببًا في «ملاحظات الفريق» (وإلا تظهر «أضف السبب»). وتحت كل اسم في الجدول: المسؤول والراعي وروابط المخرجات. البنود الفرعية («جزء من») تظهر في المصفوفة فقاعة واحدة لبندها الرئيسي مع «+عددها»، وتحته في الجدول. ويُحفظ في البند سجل ملاحظات الفريق وتوجيهات نائب الرئيس لمن سجّل الدخول.
- **الخط الزمني والتقويم**: كل بند في يومه وفي مسار نوعه، بلون حالته، ويمكن التبديل إلى التقويم (شهر، أو سنة كاملة من يناير إلى ديسمبر بتقويم صغير لكل شهر وقائمة بنوده)، مع زر «تصدير PDF» يُنزّل التقويم المعروض في صفحة A4 أفقية. وألوانه: بنود الرئيس التنفيذي بالأحمر، والفعاليات بالأخضر، وغيرها بلون مستواه (نائب الرئيس التنفيذي، نائب الرئيس، داخلي…)، ويمكن سحب أي بند فيه إلى يوم آخر لتغيير تاريخه (أو من صف «بلا تاريخ بعد» إلى يوم، أو إليه لإزالة التاريخ، ويتغيّر الشهر عند إبقاء البند فوق السهم)، والأيام تظهر كقائمة على الجوال. البنود التي بلا تاريخ في صف خاص بها.
- **المهام والفعاليات** (آخر قسم): جدول واحد يُعدَّل مباشرة، لكل بند نوع واحد ومستوى وحالة.
- **سجل التعديلات** (للمشرف فقط): يُسجَّل فيه من غيّر ماذا ومتى، باسم صاحب الحساب.

الرابط للعرض فقط لكل من لا يسجّل الدخول. يُنشئ المشرف حسابًا شخصيًا لكل من يعدّل (نائب الرئيس، أعضاء الفريق) من «إعدادات اللوحة ← المستخدمون»: اسم يظهر في السجل، واسم مستخدم، وكلمة مرور (٨ أحرف على الأقل، تُحفظ مشفّرة)، وصلاحية من ثلاث: «نائب الرئيس» أو «الفريق» أو «مشرف». يمنع الخادم حساب الفريق من تغيير غير حقوله. تغيير كلمة المرور أو إيقاف الحساب ينهي جلساته فورًا. الحساب المدمج `admin` بكلمة المرور المحفوظة في `ADMIN_PASSWORD` يبقى دائمًا حتى لا تُغلق اللوحة على أحد. عشر محاولات دخول خاطئة من العنوان نفسه توقف الدخول ربع ساعة.

**Design:** the NWC design system (`design-system/`, a locked copy of `amermalik5-gif/nwc-design-system` v1.0.0). It provides the tokens, Neo Sans W23, logos, pattern, Tailwind preset, components and rules (`design-system/DESIGN.md`).
- **`npm run ds:check`** runs before every build. It fails if the copy was edited, or if `src/` uses raw colours or fonts.
- **`npm run ds:update -- vX.Y.Z`** moves the board to a new version.
- **`/styleguide`** shows every token and component, and a test compares it with the design system's reference images.

## Stack

- **App:** React 18, Vite, TypeScript and Tailwind (`src/`). The app is Arabic and right-to-left.
- **Server:** Express with SQLite through better-sqlite3 (`server/`). It serves the built app and a JSON API under `/api`.
- **Live updates:** every open screen refreshes over Server-Sent Events (`/api/stream`) when anyone saves.

## Run locally

```bash
npm install
```

```bash
cp .env.example .env
```

Set `ADMIN_PASSWORD` in your shell or in `.env`, then start both servers:

```bash
ADMIN_PASSWORD=change-me npm run dev
```

The app runs at http://localhost:5173 and the API at http://localhost:3001. The database file is `./data/vp.db`. On first run it is seeded with the items from the kickoff meeting, all marked «بانتظار التأكيد» (awaiting confirmation).

## Deploy on Railway

1. Create a project and add a service from this GitHub repo. It builds with the included `Dockerfile` (`railway.json`).
2. Add a **volume** mounted at `/data`. The database lives at `/data/vp.db`, so it survives redeploys.
3. Set these variables:
   - `ADMIN_PASSWORD`: a long password for the admin.
   - `SESSION_SECRET`: a random string, for example from `openssl rand -hex 32`.
4. Generate a domain and share the link.

Health check: `GET /healthz`.

### Backups

- **Automatic:** a copy of the database is written once a day to `/data/backups/daily-*.db` on the same volume (newest 14 kept).
- **Manual:** the admin downloads a JSON backup from the board settings and can restore it there; the server first saves `/data/backups/before-restore-*.db`.
- **Off-site:** download a JSON backup regularly, since the daily copies live on the same volume as the database.

## API

All routes are under `/api`. Writes need a signed-in account (an httpOnly `vp_session` cookie holding a random session id, 30 days; the server keeps only its hash in the `sessions` table); the change log records that account's name. Unknown `/api` paths answer 404 in JSON.

| Method | Path | Who |
|---|---|---|
| GET | `/state`, `/stream` | everyone (`state.user` is the signed-in account, or null) |
| PATCH | `/tasks/:id` | any account; a team account only effort, progress, status, ready, start, owner, teamNotes, links, sponsor, actualEnd and parentId (rate limited) |
| GET | `/tasks/:id/history` | any account: that item's earlier team notes and VP directions |
| POST, DELETE | `/tasks`, `/tasks/:id`, `/tasks/:id/move`; POST `/events`, PATCH `/events/:id` | the VP and the admin (rate limited) |
| GET | `/audit?limit=50`, `/backup`, `/backup/tasks.csv`, `/users` | admin |
| POST, PATCH, DELETE | `/users`, `/users/:id` | admin |
| PUT | `/settings` | admin |
| DELETE | `/events/:id` | admin |
| POST | `/audit/:id/restore`, `/backup/restore` | admin |
| POST | `/login` `{username, password}`, `/logout` | everyone (10 failed attempts for one account from one address, or 30 from one address, lock it out for 15 minutes; signing out ends the session on the server) |
